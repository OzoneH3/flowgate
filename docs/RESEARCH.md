# Bounded research and reuse assessment

Reviewed 2026-10-16. These are source observations and design inputs, not claims that upstream products satisfy FlowGate's Wine requirements.

- NetLimiter [features](https://netlimiter.com/features), [gallery](https://netlimiter.com/galleries), [Activity](https://netlimiter.com/docs/user-gui-client/child-windows/activity), [Blocker](https://netlimiter.com/docs/basic-concepts/blocker), [pending requests](https://netlimiter.com/docs/basic-concepts/blocker/pending-requests), [filters](https://netlimiter.com/docs/basic-concepts/filters) and [rules](https://netlimiter.com/docs/basic-concepts/rules): adopt a dense application tree, explicit pending requests, details, and separate filters/actions. Initiation direction is distinct from byte direction. The backend's explicit permission description is groundwork for that workflow; no UI has been implemented.
- [OpenSnitch](https://github.com/evilsocket/opensnitch), including current [rule operators](https://github.com/evilsocket/opensnitch/blob/master/daemon/rule/operator.go): a useful mature reference for per-process rule evaluation. Its GPL license and existing policy model make extracting the application engine a larger integration choice. No evidence from this bounded review established safe incoming shared-Wine ownership; not imported.
- [Portmaster](https://github.com/safing/portmaster), including [NFQUEUE interception source](https://github.com/safing/portmaster/blob/development/service/firewall/interception/nfqueue_linux.go): observed separate queue directions, conntrack marking and iptables integration. Its broader DNS/service stack and GPL license are not a small reusable answer to the attribution question. No application code imported. Its policies are not assumed equivalent to this lab's failure behavior.
- [libnetfilter_queue](https://www.netfilter.org/projects/libnetfilter_queue/): queue privileges, userspace verdicts and queue-overflow behavior inform the bounded drop/retry design. Reuse [go-nfqueue v2.1.0](https://github.com/florianl/go-nfqueue) instead of introducing C bindings. Its MIT license was read locally; the module provides netlink/NFQUEUE plumbing only. An initially downloaded v1 release was retracted; go.mod/go.sum use maintained v2 instead.
- [Linux documentation](https://docs.kernel.org/) and [conntrack sysctls](https://docs.kernel.org/networking/nf_conntrack-sysctl.html): distinguish decision lifetimes from transport conntrack states. inet_diag request/response fields follow Linux UAPI; availability is tested through actual socket dumps, not a kernel-version check.
- [Wine socket server source](https://github.com/wine-mirror/wine/blob/master/server/sock.c): sock_get_fd retains the socket object's FD; handle lifecycle and async operations live in the server. Actual local Wine 11.19 PE fixtures independently showed the same socket inode in each application and wineserver. Treating that server as harmless metadata would discard an observed owner; this implementation deliberately does not do so.
- [Proton launcher source](https://github.com/ValveSoftware/Proton/blob/master/proton): STEAM_COMPAT_DATA_PATH and runtime environment are launcher implementation details, not kernel identity. Read a narrow allowlist as corroboration. No installed Steam/Proton game was launched.
- [cilium/ebpf](https://github.com/cilium/ebpf): viable optional Go loader/tooling, deferred until a concrete hook can close a measured attribution gap. BTF alone does not establish permission or distinguish shared server handles. No BPF programs installed or loaded.

Direct dependencies: go-nfqueue/v2 (MIT), mdlayher/netlink (MIT), golang.org/x/sys (BSD). Transitive dependencies remain tracked in go.mod/go.sum and retain their upstream licenses through modules. No project-wide distribution license has been selected; resolve that before distributing a release. No unsupported performance claim drove the Go choice.
