One targeted structural change
Private persistent kernel-map worker replaces per-operation process launches.
The worker has no cached map FDs or observations: each request reopens pinned
objects, performs the same operation, closes descriptors, then emits an
explicit success marker. Complete JSON alone is NOT success; an error exits
without the marker. This differs from the rejected persistent TC interpreter.
TC verification remains finite and unchanged; no batching experiment added.
Only ids/beat/health/stats/bind/del are accepted by the serial protocol.
Load/init stay one-shot. Requests<1024bytes, responses<=2MiB,3s deadline;
failure closes/reaps the child (kill after.2s grace), with no request replay.
Reconciliation, startup failure, cleanup and disabled state reap the worker.
No interval, lease, authority, class bound, cap or firewall scope changes.

Architectural conclusion
The current polling design has a significant recurring CPU floor. This one
change targets the demonstrated launch component, not fresh identity checks.
Low overhead is not established by this experiment or by crossing a70% gate.
Further discovery work would require a bounded structural design preserving
fresh authority, not cached negative permissions or slower polling.
