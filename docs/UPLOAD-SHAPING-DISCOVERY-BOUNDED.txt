Bounded native upload discovery — experimental implementation

Decision and scope
A single retained snapshot replaces repeated 1024-row censuses. The reviewed
implementation uses a global 4096-row capacity, not port sharding. It can retain
many sockets sharing one port; above its aggregate capacity it reports overload.
Port sharding remains a future option, NOT implemented: no port split can divide
arbitrarily many sockets sharing one port. There is no arbitrary-population claim.
Installed 25dbb1a and approved-update restrictions are unchanged. No host activation.

Discovery progress
Each complete dump is copied into one immutable retained generation. A scheduling
turn examines at most512 rows and submits at most8 candidate flows to the existing
fresh ResolveBatch. Cheap skips count as cursor progress. The next dump starts only
after the retained generation ends. Cap edits retain snapshot+cursor and evaluate
current configuration at consumption; the version guard discards an in-flight
result if configuration changes. Disable or empty caps drops the retained set.
No per-packet process scan is added.

For a stable supported population, every retained row receives an examination
opportunity. Worst case4096 candidate rows require512 turns (roughly8.5 minutes
at one turn/second BEFORE service time). All-cheap-skipped rows require8 turns.
New rows that arrive during consumption wait for a later generation or an existing
attribution hint. There is no wall-clock discovery SLA, no guaranteed discovery
of transient sockets under churn, and no continuous-current-owner claim.
Dump reordering cannot restart a retained cursor. Four family/protocol dumps are
not an atomic socket-table snapshot. Closed/reused rows remain hints only: fresh
ResolveBatch, cookie comparison, current config, and the unchanged controller
bind proof must all succeed before a binding can authorize SHAPING, never Allow.

Bounds, interruption and overload
4096 retained rows globally; raw accumulator <=3MiB per family/protocol request;
receive timeout2s and loop time budget2s per request (a blocked receive can extend
the loop budget by its receive timeout). There are four requests in a full dump.
The existing fresh ownership-resolution path is unchanged and is not subject to
this retained-hint limit; this increment does not claim population-independent
cost for authority checks.16 configured caps and128 bindings remain resource caps.

Any failed/interrupted dump discards its entire partial prefix. Capacity errors
use an errors.Is sentinel, not string inference. Retry delay grows1,2,4,8,16,30s,
capped at30s; a cap edit permits a fresh retry without resetting cursor progress.
Recovery can therefore wait up to30s plus scheduling/service time. A successful
dump clears backoff. Repeated overload is not retried every scheduling turn.
No completed/examined or empty-table claim is made from failed evidence.

Configuration and coverage API
CAS acknowledgement = desired configuration accepted; applied_version = controller
configuration reconciled, NOT application-wide coverage. Enabled remains Partial.
Configured caps, verified bindings and known gaps remain distinct.
discovery_snapshot exposes generation, capacity, retained_rows, cursor,
pending_rows, incomplete, overloaded, last_error, dump_duration_ms, last_dump,
last_progress, last_completed and next_retry. These describe historical hint
examination, never current completeness. Generation numbers are worker-local
(reset after disable/restart); combine with configuration/lifecycle state, not a
global socket-table version. discovery contains cumulative work
counters; discovery_overloaded is a distinct known gap. A pending or completed
pass must never be displayed as an application-wide applied cap. Shared,
unconnected/unobserved-peer sockets and first-packet races remain explicit gaps.

Independent lease maintenance
The controller no longer dumps the unrelated socket population. It asks its
private persistent probe for fresh exact generation existence, one descriptor per
binding, at most128 bindings. Descriptor: namespace, family, protocol, local/remote,
interface, cookie, inode, UID. SOCK_DIAG without DUMP queries in the worker's netns;
TCP uses ordinary tuple order, UDP the kernel's historical reversed lookup order.
The reply is validated against the original descriptor. ENOENT/ESTALE or a valid
nonmatching row means absent: delete the binding. Other errors fault the controller
and leases expire; no incomplete result becomes absence or renewal authority.

All existence reads finish before renewals begin. Each private frame <=1024bytes,
ACK deadline3s, output<=2MiB; query deadline2s; a2s total pass budget is checked
between queries (one in-flight query may extend it). A missed pass deadline faults,
not silently lengthens leases. This remains a load-sensitive limitation to measure.
No claim exact lookups are universally cheaper. The first exact existence check
also precedes installation, so an unqueryable socket form cannot enter the class.
The legacy private 'sockets -' operation remains for compatibility/tests; the
controller does not use it. Cleanup-only/disabled starts no socket worker.

Ownership contract is unchanged: bind freshly verifies application ownership;
exec/descriptor transfer does not automatically change a bound assignment. Close
or generation replacement withdraws it. Explicit rebind must prove the new owner.
No shaping evidence is reused for firewall permission. Lease duration, topology
ownership checks, foreign-object refusal and cleanup remain unchanged.
