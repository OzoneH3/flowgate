Experimental priority discovery and binding capacity
===================================================

This increment builds on 19d3770. No host activation or approved-update status.
The installed 25dbb1a release is unchanged. Upload shaping is still an isolated
supported-topology experiment, not general application-wide bandwidth control.

Priority contract
-----------------
A newly added or rate-changed cap schedules one bounded native process/descriptor
observation. The application key derived from UID and the observed executable
path is ONLY a candidate hint. It does not prove native runtime identity, current
ownership, process generation or a permission. Private thread descriptor tables,
foreign mount path translations, inaccessible processes and newly arriving
sockets may be missed. No display label, parent or command line is authority.

The scan reads /proc and matching leader fd directories in batches of 64 entries:
4096 numeric process entries, 16384 fd entries globally, 128 unique inode hints,
and a 250ms work deadline checked between operations. An individual syscall is
not given a hard deadline. Reaching a bound or a non-disappearance I/O failure is
reported as incomplete. There is no periodic process hint polling. Disabled
shaping has no new worker or polling. Configuration acknowledgement performs no
hint I/O; the worker performs it outside configuration and policy locks.

Hints select at most128 unique rows from the retained complete snapshot, including
rows behind its cursor. If there has not yet been a complete snapshot, selection
waits for one. Sockets absent from that generation produce snapshot_not_present
and use ordinary discovery or existing attribution offers; no extra full census
is added. A snapshot is historical and may become stale immediately.

Each discovery batch still has at most8 fresh ResolveBatch candidates. At most4
priority rows are attempted, reserving space for at least4 background candidates
when available within the bounded scan. Repeated cap changes supersede priority
work but do not reset background snapshot/cursor progress. Cookie deduplication
prevents the same row being resolved twice in one batch. All selected rows require
fresh resolution, generation equality, the current cap/version and the controller's
unchanged full binding proof. Exec, shared ownership, descriptor transfer and
socket reuse cannot gain a binding through a stale hint.

priority_discovery reports version, hint_inodes, pending_rows, attempts,
incomplete/reason, hint_duration_ms and completed. Completion means this bounded
hint attempt finished; it never implies complete application coverage. Existing
configured_caps, applied_version, actual kernel bindings and receiver delivery
remain distinct. AppliedVersion means controller configuration reconciled, not
that all application sockets have been found. Status remains Partial.

Provisional responsiveness objective (not a supported latency guarantee):
acknowledgement <2s, first verified binding and receiver-observed cap within15s of
acknowledgement for one stable target among<=16 priority sockets, within the above
observation limits and PRESENT in the retained snapshot. Missing/private-table/
new-generation sockets, overload and scan limits have no such deadline. The
background worst case remains512 turns for4096 candidate-heavy rows. This
increment must not disguise that fallback delay as a fully applied app-wide cap.

Maintenance measurements
------------------------
KernelStatus adds maintenance_cycles, maintenance_pass_ms,
max_maintenance_pass_ms, max_completion_gap_ms and max_renewal_span_ms. These are
monotonic-time timing observations from successful controller ticks (maxima are
controller-lifetime maxima). Full maintenance includes verification, offload
observation, exact existence queries, removal/renewal, class retirement and beat.
Renewal span includes the renewal loop through beat. Durations round upward.
No lease duration, check, RPC deadline or authority semantics changed.

For a continuously present binding and successful cycles, maximum completion
gap plus maximum renewal span is a conservative bound on inter-renewal spacing.
Failure paths still fault or expire as before. Direct kernel health snapshots
supply sampled remaining margins; samples alone are not continuous kernel trace.
A test with128 bound sockets is not evidence of128 simultaneously bulk-active
sockets unless that workload is separately recorded.
