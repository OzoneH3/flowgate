Segmentation-enabled upload shaping (isolated proof, no host activation)

Scope
Continues docs/UPLOAD-SHAPING-PREFLIGHT.txt. The isolated controller now accepts a
single-queue default-fq_codel NIC whose TSO/GSO features are ON, sizes its
classes for superpackets, and reports what it observed. Offloads are never
changed by the controller. The host NIC enp7s0 (r8169, TSO/GSO on) is the
target configuration; it is still refused by the mandatory child-namespace
guard and no host flag exists. Download, VPN, priorities and UI are deferred.
Installed release 25dbb1a, rules, protection and updater safeguards unchanged.

Why the previous virtio fixture could not carry this proof
QEMU clears every virtio-net offload feature when its network backend lacks a
virtio-net header; the unprivileged backends (hubport, socket, stream, user)
all lack it. The guest NIC therefore reports tx-scatter-gather and all
segmentation features "off [fixed]", and the kernel refuses GSO without SG.
"TSO/GSO enabled" was unreachable on that device, not merely unproven.
Backends with offload support (tap, vhost-user, passt) need host privileges or
route guest traffic into the host network; both are excluded.

Segmentation fixture device: netdevsim
netdevsim is the kernel's software NIC simulator (CONFIG_NETDEVSIM=m, loaded
only by root inside the disposable guest). Two single-port devices are
peer-linked through /sys/bus/netdevsim/link_device. Each port is a plain
Ethernet netdev with parentbus "netdevsim", one TX queue, tx_queue_len 1000
(kernel-default fq_codel root, handle 0:), scatter-gather, TSO and GSO on,
tx-udp-segmentation off (UDP_SEGMENT superpackets are segmented in software
after the qdisc), hw-tc-offload present but off, gso_max_size 65536.
The classifier, HTB and fq_codel path is identical to a physical NIC. What
differs is after dequeue: netdevsim forwards GSO skbs to its peer unsegmented,
a real NIC segments in hardware. netdevsim is therefore software-path evidence
only; it proves nothing about virtio or r8169 hardware offload behaviour.
compatibility() accepts parentbus netdevsim as a NIC bus. It never exists on a
host unless an administrator loads the module; interface support is not
otherwise broadened and the namespace guard is unchanged.

Sizing with superpackets (NIC topologies; the veth M1 sizing is unchanged)
 superpacket S  = max(gso_max_size, gso_ipv4_max_size, tso_max_size)   [65536]
 HTB burst      = max(2·MTU, S, rate·5 ms)        token-bucket size
 leaf memory    = min(max(256 KiB, 16·S), max(2·MTU, 3·S, rate·25 ms))
 leaf packets   = 128, FQ-CoDel target 5 ms, interval 100 ms
Charged bytes versus skb length: HTB and fq_codel charge qdisc_pkt_len, which
for a GSO skb is skb->len plus the repeated per-segment headers
((gso_segs - 1) x header length). The largest charged packet measured on
netdevsim was 68130 B for a 65536 B superpacket (tc "maxpacket"). S is
therefore the advertised payload bound, not a universal charged-byte bound:
the token bucket (burst >= S) can be exceeded by one charged superpacket, i.e.
the measured deficit is at most 68130 - 65536 = 2594 B beyond the bucket, repaid
before the next dequeue. The classifier counters use skb->len, so classifier
bytes and class dequeued bytes differ by exactly these header charges (plus
drops between hook and dequeue); the three figures are reported separately.
Burst allowance: HTB is a token bucket refilled at the configured rate. One
superpacket is always admitted once the bucket is non-negative and its deficit
is repaid before the next dequeue, so the transient excess over the long-run
rate is bounded by one bucket plus at most one charged superpacket; it is not
a renewed free allowance per interval. The actual per-application burst and
leaf memory limit are reported in status.segmentation.per_app_burst_bytes /
per_app_leaf_memory_limit (for example 65536 B at 8 Mbit/s, 625000 B at 1 Gbit/s).
fq_codel memory_limit counts skb truesize (payload plus page/header overhead),
so 3·S is a configured threshold that leaves room for two queued superpackets;
it is not a payload guarantee. This iproute2's JSON exposes no memory_used, so
the evidence records the configured threshold plus sampled backlog/qlen (1 s
sampling); no peak-memory claim is made.

UDP_SEGMENT: rate gate FAILED / inconclusive (measured, VM3/VM4)
Tested path: original-direction UDP of an allowed application in protection
mode "both", i.e. the intercepted NFQUEUE path (queue opened with the conntrack
flag only, no GSO passthrough, 128-entry queue). On that path the kernel
segments GSO skbs before handing them to the queue, so the application's
UDP_SEGMENT superpacket arrived at the egress hook as ordinary segments: 2197
datagrams of 64000 B (140.6 MB) offered with UDP_SEGMENT 1400 in 6 s produced 0
superpackets and 715 ~1400 B segments (1.03 MB) at the hook, 996 KB at the
receiver. That is queue saturation (the 8 Mbit/s shaper was underfed at about
1.4 Mbit/s), so UDP cap accuracy at the target rate was NOT measured; this gate
is recorded as failed/inconclusive, not as a pass. The observation is scoped to
this intercepted path: reply-direction, bootstrap or otherwise non-intercepted
UDP can behave differently and no universal "UDP is never GSO at the shaper"
claim is made. Established TCP bypasses the queue, which is why TCP superpackets
do reach the hook; the segmentation evidence for shaping is therefore TCP-only.
Candidate smallest change for a later increment: GSO passthrough on the queue
(one verdict per superpacket). It changes firewall packet parsing and length
accounting, queue bounds (bytes and segments), verdict semantics and fairness,
and is a separate reviewed firewall increment, not made here.

Supported-rate profile with segmentation
CoDel target/interval are not hard latency bounds. Serialization alone costs: 64 KiB takes 524 ms at
1 Mbit/s, 65 ms at 8 Mbit/s, 16 ms at 32 Mbit/s. TCP keeps its own superpackets
small at low rates (autosizing to about 1 ms of pacing rate, minimum two
segments); explicit UDP_SEGMENT applications choose their own size. The
controller reports recommended_min_rate_bps = 10 superpackets per second
(5.24 Mbit/s for 64 KiB). Caps below that remain enforced for throughput; the
capped application's own latency can degrade. Independent classes do not
guarantee independent throughput under CPU contention (the default-traffic
gate below failed). Cap accuracy was measured at 2, 8 and 32 Mbit/s TCP;
the attempted 8 Mbit/s UDP_SEGMENT rate gate was inconclusive; higher rates up to the 1 Gbit/s configuration
bound are not validated in the guest.

Measurement methodology (experimental/upload-shaper/segmentation/run.py)
Three figures are always kept separate: classifier bytes (clsact egress hook,
enqueue attempts, including later drops and retransmits), HTB class dequeued
bytes (tc -s class; what the scheduler released) and receiver payload (peer
bulk accounting by source flow). Each rate phase samples all three once per
second during 6 s of saturating bulk. class_accuracy = class bytes / (rate ×
wall interval including ramp and drain); steady_accuracy = median per-second
class rate / rate over the interior seconds. Segmented skbs reaching the
shaping path are proven by classifier counters index 2/3 (GSO skbs with
gso_segs > 1, classified / not classified), index 4 (segment sums; the raw
struct's packets/bytes fields hold classified/unbound segment counts) and the
leaf's maxpacket exceeding two MTUs. These counters change no class selection
and are never permission evidence. The guest is a single TCG vCPU: uncapped
throughput is CPU-bound and reported only as a ratio against a baseline taken
through the untouched default root before takeover.

Remaining hardware-specific limitations
- netdevsim exercises software GSO handling at the qdisc; hardware TSO on r8169
  (rtl8126a), checksum offload interaction, driver TX ring behaviour, link
  resets and real wire timing are not exercised.
- virtio on the internal hub cannot enable SG/GSO at all; virtio-with-offloads
  behaviour (vhost/tap) remains untested without host privileges.
- fq_codel truesize accounting versus payload differs per driver allocation
  pattern; the 3·S threshold is validated only on netdevsim allocations.
- UDP_SEGMENT (64000-byte datagrams, 1400-byte segments, IPv4) on the intercepted
  path was pre-segmented and queue-saturated: UDP superpacket shaping and UDP cap
  accuracy are NOT demonstrated (failed/inconclusive gate). IPv6 UDP GSO,
  sendmmsg batching and non-intercepted UDP paths are not measured.
- Rates above 32 Mbit/s, multi-queue NICs, VLAN/bond/bridge, Wi-Fi and BIG TCP
  (gso_ipv4_max_size/gso_max_size above 64 KiB) are outside the measured scope;
  maxima above 262144 are refused.
- 1 s sampling cannot observe sub-second queue peaks.

Opt-in host validation plan (NOT executed; requires explicit user approval)
1. Preflight only (read-only): run `controller.py --preflight` against enp7s0
   from the host namespace to record the matrix, maxima and root options.
   Expected: profile segmentation-capable, hw-tc-offload off, supported=true
   except for the namespace guard.
2. Add an explicit host-interface opt-in flag, separate from the lab namespace
   guard, reviewed and defaulted off. Recovery must use the controller
   cleanup-only path with the original private ownership journal: verify
   interface generation, namespace, pinned program/map IDs and owned TC
   topology before removing owned objects, then check restoration. On an
   ownership mismatch, refuse mutation and report the evidence for review.
   Bare root-qdisc deletion is not a normal recovery procedure; absent or
   ambiguous ownership requires manual diagnosis, not automatic deletion.
3. User-approved window with no other traffic: takeover, one capped TCP flow at
   8 and 32 Mbit/s to a LAN receiver for 30 s each, one UDP_SEGMENT flow,
   baseline/during/after throughput of an uncapped flow, then disable and
   verify the exact default root is restored. Record the three byte figures,
   peak leaf memory, receiver latency and `ethtool -S` TX counters.
4. Lifecycle under NetworkManager: link down/up, MTU change, offload toggle by
   the administrator (expect reported limitation, no revert), reboot with an
   active journal (expect Unsupported then journal-only forget).
5. Only after that evidence: matched release candidate, review, activation
   approval. Never change offloads silently; never replace a non-default root.
