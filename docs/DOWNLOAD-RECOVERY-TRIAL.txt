Scope
-----
Shared UL/DL architecture, API, UI, socket attribution, five-second leases and

Recovery contract
-----------------
Before each IFB root/class/leaf add, journal the exact command, detailed before
queues, intended detailed after queues and phase-specific UL template provenance.
Templates are taken at each corresponding UL startup phase, before any app caps;
the final UL tree cannot be used because leaf creation changes class.leaf.
IFB MTU is set to the selected interface MTU before UP. HTB direct_qlen is explicit
using the verified IFB txqlen (minimum 2), preserving the tested default 32.
Only major/device and direct_qlen differ from the same-kernel UL phase. Detailed
JSON retains all reported configuration fields; only reference-count and direct
packet counters use the existing structural normalization.

Normal completion and restart compare exact detailed results. The accepted
detailed checkpoint remains durable while startup is pending, including crashes
after the add journal commit and before the next operation. Restart permits
only the unchanged before-state or intended after-state. Foreign filters, IFB
identity, program IDs, parent/handle and outside-IFB differences refuse cleanup.
The private owner journal remains; pending-ifb-mismatch.json records intended,
observed and ordinary topology evidence. IFB link-identity refusal retains the
journal and explicit error instead. No handle-only fallback for legacy pending
adds. Additional detail checks run before each pending cleanup mutation, not on
the steady-state loop. Kernel dumps/checks are not atomic against privileged
concurrent mutation; this is not an adversarial root security boundary.
