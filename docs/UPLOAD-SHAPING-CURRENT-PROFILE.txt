One targeted change
Controller tick reuses one private socket census probe process. Every request
still executes fresh SocketsLimited(1024); there is no socket/evidence cache,
negative TTL, changed interval, changed ownership contract or topology reuse.
Finite probe bind (fresh ownership proof), permission authority, discovery,
TC verification, lease renewal/expiry and foreign-object refusal are unchanged.
Only repeated Go process startup is removed; the .925s includes actual census
work that remains. No predicted CPU floor, throughput ceiling or gain is claimed.

The worker is lazy, serial, private stdin/stdout only, no network listener.
Exact request 'sockets -', 1024-byte input bound,2 MiB output including framing,
3 s controller deadline, explicit success ACK after complete census/encoding.
A partial/error census produces no ACK; broken/short output and timeout fail.
The controller closes/reaps the worker on fault/cleanup, including cleanup refusal.
Disabled and cleanup-only modes create no socket worker. Worker death is a new
fault source: controller becomes Unsupported, leases bound stale classifications,
and explicit CAS configuration is required to resume. No automatic replay.

Architecture assessment
Repeated finite processes are measurable avoidable work; persistent fresh-query
mechanisms can remove startup while preserving evidence. This experiment does
not establish that process reuse alone can meet low-overhead operation. Reusing
an older topology observation in status was considered and declined because it
would change verification freshness. Other architectural changes require their
own evidence and review; none are bundled here.

HTB bytes versus receiver payload. 1,200 low-rate records/phase; same six status

Fresh worker PID stays stable throughout candidate phase and absent when disabled;
new worker killed in failure phase, then Unsupported/explicit disable/exact

Disposition
Retain the small isolated startup reduction as experimental, independently
reviewed. No release is approved or deployed. Both engineering performance
objectives remain unmet; no physical-host trial is proposed from this result.
No further optimization bundled. Remaining cost of the resulting candidate was
not re-profiled; the profile above belongs to its exact 4563bc40 baseline.
A larger reduction still requires fresh-query control/discovery architecture
work, selected and validated from evidence rather than weaker freshness checks.
