## 3. Fast path + shaping coexistence (production startup path)
- Start through `serve` with the launcher's flags (record the argv and diff it against the installed
  `launch` argv; any difference is listed). Continuous protection must be started through the
  protection-session owner. Require `socket_authorization.route_bound == true` and production-session
  status. The lab `StartSocketAuthorization` is not acceptable evidence.
- **Same-flow proof** per cell where A's UDP is accelerated:
  1. UDP-only window: no A TCP sockets exist and no other A traffic. Send N datagrams of size S on the
     single connected UDP socket. Take tc snapshots immediately before and after the window, before
     any PING or other traffic. If PING shares the socket, include its packet count explicitly.
  2. Class key (only in cells where `app_ul_class`): the unique non-reserved HTB leaf (minors ∉ {fff0, fff1,
     fffe}) on DEV. Assert that exactly one such leaf exists for an unzoned A and that its (rate×8, ceil×8, prio)
     equals both the v2 tuple and `traffic_priority.apps[A].upload`. `tc -j` rate/ceil are bytes/s; record
     the iproute2 version because burst/cburst units vary. Otherwise the cell is **Inconclusive**.
  3. HTB charges at DEQUEUE. Take the after-snapshot only once that leaf's qdisc backlog is 0 (poll ≤ 2 s;
     else Inconclusive). Then the expected class delta is `packets == N_sent − sender_errors − leaf_drops`
     and `bytes == packets × (S + 28 + 14)` (S ≤ MTU−28, no hardware VLAN), exact.
     Fast hit delta over the same window ≥ N_sent − sender_errors (hits are counted before the qdisc).
     Receiver count == class packets (dequeued packets that were not received are unexplained, §5).
  4. Where `queues.app_ul_class` is false: the app leaf delta must be 0. With a UL budget the packets
     are charged to fffe, otherwise to fff1 or unshaped (negative check). Note that fffe always exists in tc
     at 100gbit; "default class in budget mode" means status `traffic_priority.default_class.upload` is non-null.
     A priority-only entry with neither caps nor budget DOES get a binding with no class (minor 0,
     upload_class=false, still uses one of the 16 slots). Never treat "a binding exists" as class evidence.
  5. A second, unconfigured app B sends a UDP stream in a separate window: its packets must not appear
     in A's leaf. This is the cross-app negative.
- Fast continuity: hits keep growing across every edit, and the grant's closed/refused counters only change
  where the contract expects revocation (none for shaping edits). Record admission time vs delivery.

## 4. Cap and budget ceilings (replaces the blanket ×1.25)
Each counter snapshot is taken inside an RPC bracket [request sent, reply received] on the guest
monotonic clock. Record the raw bracket times for every snapshot.
- `T_max = end_reply_received − start_request_sent` is the longest interval in which the counted bytes
  can have arrived. **All upper-ceiling (compliance) checks use T_max**, so a compliant shaper is never
  failed by sampling uncertainty. `T_min = end_request_sent − start_reply_received` is reported only as
  the upper end of the throughput estimate ([bytes/T_max, bytes/T_min]). It is never used for a ceiling.
- L = the class's **ceil** (the long-run limit; with a budget, rate is only the floor and is below ceil).
  T = T_max as defined above.
- Charged-bytes check (correct units: HTB counts L2 skb bytes at dequeue): `Δclass_bytes × 8 ≤ L × T_max + 8 × (burst + cburst + one max skb)`
  (the last term is HTB's one-packet overshoot).
  burst/cburst come from `tc -s -j class` of that leaf. The tc snapshots use their own brackets.
- Receiver payload check: `payload_bytes × 8 ≤ L × T_max + 8 × (burst + cburst + backlog0 + one max skb)`.
  backlog0 is that leaf qdisc's backlog bytes at window start. Max skb is 65536 with segmentation offload,
  else the MTU. For DL add the exact pending bytes at window start (fixture FIONREAD / RECVQ), not the buffer size.
- Payload is always ≤ charged bytes for the same flow set. Report both. Payload > charged + backlog0 is a
  measurement error, which makes the cell **Inconclusive**, not Pass.
- Window ≥ 3 s after ≥ 2 s settling. **Two consecutive windows** must both satisfy the bound. An excess
  in either window is sustained overshoot and fails unless it is explained by a listed term.
- Budgets use the same formula with the fff0 class tuple.
- Lower-than-cap throughput is reported, never failed. TCG cannot establish capacity.

## 5. Loss taxonomy (every missing datagram is classified)
`missing = sent_ok − received`. Explained by, in order:
1. `sender_errors`: ENOBUFS/EAGAIN at sendto (fixture counts).
2. `shaping_queue_drops`: Δdrops of the leaf fq_codel/HTB for the expected class. These are deliberate
   throttling only when the class's cap or budget is saturated in that window.
3. `startup_admission`: packets before the grant or first verdict (fast/queue) and queue rejection
   deltas (`queue_health` attribution/retention capacity rejections).
4. `attribution_failure`: shaper gaps (`unsupported_or_shared_observation`, `binding_refused`) or
   firewall unresolved-owner drops.
   Gap names include `unsupported_or_shared_observation`, `unsupported_or_shared_discovery`, `unsupported_flow`,
   `binding_refused` (read all keys of `Gaps`; do not filter).
5. **unexplained** = remainder. Unexplained > 0 fails in quiet windows. Under load it is reported
   per cell and fails if > 0.5 % of sent or > 2 packets, whichever is larger.
UDP loss is never labelled "expected shaping" without category 2 evidence.

## 6. Applying windows (temporary unshaped intervals)
During each configuration edit, run a constant UDP probe from A (e.g. 200 pps). Sample tc every 100 ms
from the CAS request until `applied_version` is reached plus 1 s. Report the probe packets charged to fff1
(bypass) or not charged to the expected class while Applying, the duration and `upload_lease_expired_bypass`
deltas. The documented behaviour is a brief unshaped window on flat↔interior or budget transitions.
Report the measured window. `applied_version` does NOT prove socket coverage (TRAFFIC-PRIORITY.txt:95-96). A newly
configured socket legitimately bypasses until it is bound: queue hint in protected mode; shaper census (~1 s) in off mode
and for accelerated flows in fast mode. Report time-to-class per mode. **Fail** only if the A probe still reaches
fff1/unshaped after that socket's binding reports the expected class for its cookie (+1 s), or if an already-bound
socket loses its class beyond the documented directional conversion window.

## 7. Focused priority tests (core cells do not establish priority effectiveness)
- **P1 saturation swap:** apps A and B (distinct executables), no caps, UL and DL budgets of 16 Mbit/s.
  Each app offers ≥ 2× the budget (4 TCP sockets each per direction). Offered load stays unchanged
  across phases: phase 1 A=Low/B=High, phase 2 swapped, phase 3 both Normal (control). 2 s settle +
  2 × 4 s windows. Phase order: A-low → A-high → control → **A-low again** (drift/hysteresis check).
  (v2.1) The former fixed 1.5 ratio is withdrawn. No document promises a share or ratio; the contract
  only claims that High is favoured over Low when borrowing under a saturated budget. The assessment
  therefore tests the claimed direction against this fixture's own measured variability:
  - Preconditions per window and direction (otherwise **Inconclusive: not saturated**): fff0 charged rate
    over T_max ≥ 0.9 × budget ceil, fff0 overlimits increased, aggregate ≤ §4 budget bound.
  - N = the largest |window0 − window1| of any app rate within one phase (repeatability).
    C = |r_A − r_B| in the control phase (app asymmetry with no priority; both share fffe).
    D = |r_A(A-low, first) − r_A(A-low, repeat)| (drift).
  - Effect per swapped phase: Δ = r_High − r_Low. Swap response: S_A = r_A(A-high) − r_A(A-low),
    S_B = r_B(A-low) − r_B(A-high).
  - **Effective (Pass):** in both swapped phases Δ > C + 2N, AND S_A > 2N and S_B > 2N (each app gains
    when it becomes High), AND D ≤ 2N + 0.05 × aggregate.
  - **Ineffective (Fail):** preconditions met and 2N < 0.25 × aggregate, but Δ ≤ C + 2N in either phase, or
    S_A / S_B ≤ 2N or of the wrong sign.
  - **Inconclusive:** preconditions not met, 2N ≥ 0.25 × aggregate (too noisy to resolve), or drift D too large.
  - Report the magnitudes (rates, Δ, S, ratios, Δ/aggregate) as observations only. Prior physical evidence
    at a 40 Mbit/s budget (≈ 35 vs 4 Mbit/s, 517f001d) is context, not a threshold.
  An ineffective priority can never pass: Pass requires a direction-correct, swap-responsive effect larger
  than the fixture's own noise and app asymmetry. Run per direction (UL and DL are assessed separately).
- **P2 game-like flow:** app C sends 64 kbit/s UDP (e.g. 100 B @ 125 pps) with sequence-matched echo.
  App D runs bulk TCP saturating the UL budget. Phases: no budget (reference); budget with C=Normal,
  D=Normal; budget with C=High, D=Low; and the swap C=Low, D=High. Report the echo RTT
  p50/p95/p99/max and loss by §5 category, separately per phase. Expected: under the budget, C=High
  has p95 ≤ the C=Normal phase and no unexplained loss. Otherwise mark it **Fail (no observable benefit)**.
  If phase variance exceeds the difference across 3 repeats, mark it **Inconclusive**. The same saturation
  precondition as P1 applies to every budgeted phase; an unsaturated budget gives **Inconclusive**.
  The C=Normal comparator means both apps are unconfigured and share fffe, since a Normal-only entry is invalid.
  No latency bound is asserted.
- Run P1/P2 in protected and fast (P2 C is accelerated in fast) and off, so the comparison roles of §8 apply.
